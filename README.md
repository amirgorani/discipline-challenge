# برنامه‌ریز انضباط روزانه — فرانت‌اند GitHub Pages + بک‌اند Supabase

چالش انضباط روزانه فارسی و راست‌چین با احراز هویت واقعی، دیتابیس PostgreSQL و امنیت Row Level Security — **بدون هیچ سرور اختصاصی**.

## معماری

| لایه | تکنولوژی |
|---|---|
| فرانت‌اند (ایستا) | HTML/CSS/JS روی **GitHub Pages** |
| احراز هویت | **Supabase Auth** (ثبت‌نام / ورود / خروج با ایمیل و رمز) |
| دیتابیس | **Supabase PostgreSQL** (جدول‌ها + RLS) |
| کلاینت | `@supabase/supabase-js` رسمی از CDN، فقط با **کلید عمومی anon** |

> ⛔ کلید `service_role` هیچ‌وقت در کد فرانت‌اند قرار نمی‌گیرد. ایزولیشن داده‌ها فقط با RLS تضمین می‌شود.

> 🛡 **پنل مدیریت** (admin.html) با همین معماری کار می‌کند: فقط کلید anon، نقش مدیر در دیتابیس، سیاست‌های RLS مخصوص مدیر و اقدامات حساس با توابع امن (security-definer) + ثبت در گزارش فعالیت. راه‌اندازی: ابتدا `schema.sql`، سپس `supabase/admin-schema.sql` را در SQL Editor اجرا و یک مدیر ارشد معرفی کنید (بخش راه‌اندازی پایین).

## راه‌اندازی قدم‌به‌قدم (یک‌بار، حدود ۱۰ دقیقه)

### ۱. ساخت پروژه Supabase
1. در [supabase.com](https://supabase.com) حساب بسازید و **New project** بزنید.
2. صبر کنید پروژه آماده شود.

### ۲. ساخت جدول‌ها و سیاست‌های امنیتی
1. در داشبورد Supabase وارد **SQL Editor → New query** شوید.
2. محتوای کامل فایل **`supabase/schema.sql`** همین ریپو را کپی و **Run** کنید.
3. این فایل می‌سازد: `profiles`, `challenges`, `mandatory_rules` (۶ قانون ثابت)، `custom_tasks` (با ستون توضیحات)، `daily_submissions`, `daily_scores`, `schedule_items` + همه RLS policyها + تریگر ساخت پروفایل هنگام ثبت‌نام.
4. اگر قبلاً اسکیمای قدیمی را اجرا کرده‌اید، فقط فایل **`supabase/migration-002-task-descriptions.sql`** را اجرا کنید تا ستون توضیحات اضافه شود (برنامه بدون آن هم با حالت سازگار کار می‌کند).

### ۳. ساده‌سازی ورود (تست)
- در **Authentication → Sign ups** گزینه **Confirm email** را **خاموش** کنید تا ثبت‌نام بلافاصله وارد حساب شود.

### ۳.۵ راه‌اندازی پنل مدیریت (اختیاری)
1. در همان **SQL Editor** محتوای فایل **`supabase/admin-schema.sql`** را اجرا کنید (نقش/وضعیت حساب، سیاست‌های RLS مدیر، توابع امن، گزارش فعالیت، آرشیو وظایف و همه ستون‌های لازم — افزودنی و بدون دست‌کاری داده‌های موجود).
2. حساب اولین مدیر ارشد را بسازید: در برنامه اصلی (index.html) ثبت‌نام کنید، سپس در SQL Editor بلوک کامنت‌شدهٔ انتهای `admin-schema.sql` را باز کنید، جای ایمیل، ایمیل حساب خودتان را بگذارید، **Run** کنید و دوباره کامنت کنید.
3. آدرس **`admin.html`** را باز کنید و با همان حساب وارد شوید. فقط حساب‌های دارای نقش «مدیر» یا «مدیر ارشد» وارد پنل می‌شوند؛ کاربران عادی پیام «دسترسی غیرمجاز» می‌بینند و داده‌های مدیریتی هم در سطح دیتابیس برایشان مسدود است.
4. منوی «تنظیمات مدیریت» داخل پنل راهنمای ارتقای مدیران بعدی را دارد (ارتقا با تأیید و ثبت در گزارش فعالیت).

### ۴. گرفتن مشخصات اتصال
- در **Settings → API** این دو مقدار را کپی کنید:
  - **Project URL** (مثل `https://xyzcompany.supabase.co`)
  - **anon public key** (کلید عمومی — نه service_role)

### ۵. اتصال برنامه
دو راه دارید (هر دو فقط از anon key استفاده می‌کنند):
- **الف) صفحه راه‌اندازی برنامه:** برنامه را باز کنید، URL و anon key را وارد و «بررسی اتصال و ذخیره» را بزنید (فقط در همان مرورگر ذخیره می‌شود).
- **ب) فایل پیکربندی:** فایل `supabase-config.example.js` را به نام `supabase-config.js` کپی و مقادیر را پر کنید. این فایل در `.gitignore` است و کامیت نمی‌شود.

### ۶. انتشار روی GitHub Pages
```powershell
git init
git add .
git commit -m "Persian discipline challenge tracker (Supabase backend)"
gh repo create daily-planner --public --source=. --push
# Settings → Pages → Deploy from branch → main → / (root)
# آدرس: https://<you>.github.io/daily-planner/
```
فایل‌های `index.html` ،`styles.css` ،`js/` ،`supabase/` کافی‌اند؛ بدون build و بدون سرور.

## مدل داده و ایزولیشن

- هر کاربر فقط ردیف‌های خودش را می‌بیند: چالش‌ها با `user_id = auth.uid()` و جدول‌های وابسته (`custom_tasks`, `daily_submissions`, `daily_scores`) فقط از طریق چالشی که مالک آن است.
- `mandatory_rules` برای همه فقط خواندنی است؛ قوانین اجباری از سمت کاربر قابل حذف نیستند.
- داده‌ها روی سرور Supabase ذخیره‌اند: بین دستگاه‌ها، نشست‌ها و مرورگرها ماندگار.

## پنل مدیریت — مدل امنیتی (admin.html)

| لایه | مکانیزم |
|---|---|
| نقش مدیر | ستون `profiles.role` (`user` / `admin` / `super_admin`) + `account_status` (فعال / معلق) — فقط با RPCهای امن تغییر می‌کند و در گزارش فعالیت ثبت می‌شود |
| دسترسی داده مدیر | سیاست‌های RLS «خواندنی» با تابع امن `is_admin()` — کاربر عادی طبق سیاست‌های قبلی فقط داده خودش را می‌بیند |
| حفاظت ستون‌ها | گرنت‌های ستونی (مثلاً update فقط روی `username`) + تریگر `guard_profile_admin_columns` |
| اقدامات حساس | `admin_set_user_status` / `admin_set_user_role` با تأیید در رابط، بازرسی نقش سمت سرور و ثبت: مدیر انجام‌دهنده، طرف، زمان و جزئیات |
| فعالیت کاربر | `last_login_at` / `last_activity_at` / `last_submission_at` — ورودها و ثبت‌های روزانه ردیابی می‌شوند |
| آرشیو وظایف | `custom_task_history` عنوان وظایف حذف‌شده را نگه می‌دارد تا نگاه تاریخچه روزها در پنل، همیشه دقیق بماند |
| گزارش فعالیت | جدول `admin_audit_logs` + صفحه «گزارش فعالیت‌ها» با فیلتر و صفحه‌بندی |

بخش‌های پنل: **نمای کلی** (آمار کل + نمودارها) · **کاربران** (جستجو/فیلتر/صفحه‌بندی/پرونده کاربر) · **کاربران فعال** (تفکیک فعالیت از وضعیت حساب) · **چالش‌ها** (نمای همه چالش‌ها + تقویم روز به روز هر چالش با امتیاز، قوانین و وظایف اختیاری همان روز) · **تحلیل عملکرد** (روندهای روزانه/هفتگی/ماهانه، نرخ قوانین، مثبت/منفی، حکم بهبود/ثبات/افت) · **گزارش فعالیت‌ها** · **تنظیمات مدیریت**.

## کار روزانه فقط از داشبورد
1. داشبورد را باز کنید — کارت **«⚡ ثبت سریع امروز»** هر ۶ قانون اجباری و وظایف اختیاری امروز را نشان می‌دهد.
2. با **یک کلیک** هر مورد را انجام‌شده / انجام‌نشده کنید (پیش‌نمایش امتیاز زنده به‌روز می‌شود).
3. **«💾 ذخیره نتیجه امروز»** را بزنید — یک سطر یکتا در `daily_submissions` + رکورد امتیاز در `daily_scores` ذخیره و آمارها به‌روز می‌شود؛ پیام موفقیت/خطا نمایش داده می‌شود.
4. کارت **«🛠 شخصی‌سازی وظایف»** در همان داشبورد: افزودن (عنوان + توضیح)، ویرایش با دکمه ذخیره، حذف — بدون اثر روی سوابق روزهای گذشته (حالت‌ها با شناسه وظیفه ذخیره می‌شوند و وظایف جدید عطف‌به‌ماسبق حساب نمی‌شوند).

## طراحی ریسپانسیو

رابط موبایل‌فرست است: تک‌ستون در موبایل با **ناوبری پایینی ثابت**، دو ستون در تبلت، و چندستون در لپ‌تاپ/دسکتاپ (تا ۱۲۸۰px). جدول‌ها اسکرول داخلی دارند، تقویم در موبایل فشرده با نام روزهای کوتاه می‌شود، ورودی‌ها ۱۶px هستند (جلوگیری از زوم iOS)، و `prefers-reduced-motion` و حالت‌های فوکوس صفحه‌کلید پشتیبانی می‌شود. تست‌شده در ۳۲۰ / ۳۷۵ / ۴۳۰ / ۷۶۸ / ۱۰۲۴ / ۱۳۶۶ / ۱۹۲۰ پیکسل بدون اسکرول افقی صفحه.

## مدل شفاف امتیازدهی
- هر قانون اجباری در روز **۰ تا ۱۰ امتیاز مثبت** (جمعاً ۶۰). مطالعه/ورزش/هدف نسبی (مثلاً ۵ صفحه = ‎+۵)، بیداری/الکل/دود صفر یا ۱۰.
- **امتیاز منفی/از دست رفته** = ۶۰ − امتیاز کسب‌شده. روز از دست رفته (گذشته و بدون ثبت) = صفر و به‌صورت رکورد `missed` در `daily_scores` ذخیره می‌شود.
- **درصد روزانه** = امتیاز ÷ ۶۰ × ۱۰۰. **امتیاز کلی چالش** = مجموع ÷ (۶۰ × روزهای سپری‌شده از شروع) × ۱۰۰.
- هر وظیفه اختیاری انجام‌شده = **‎+۲ تشویقی جدا** (سقف روزانه ‎+۱۰)، بدون جریمه و بدون اثر در درصد اجباری.
- همه آمارها (ثبت‌شده/از دست رفته/رشته موفقیت/روندها) فقط از **تاریخ شروع چالش** محاسبه می‌شوند؛ روزهای قبل از شروع هرگز شمرده نمی‌شوند.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| «جدول‌های دیتابیس ساخته نشده‌اند» | `supabase/schema.sql` را کامل در SQL Editor اجرا کنید |
| ثبت‌نام موفق ولی ورود نه | Confirm email را خاموش کنید یا ایمیل را تأیید کنید |
| «نشست منقضی شده» | دوباره وارد شوید |
| خطای اتصال | URL و anon key را بررسی کنید؛ service_role استفاده نکنید |
